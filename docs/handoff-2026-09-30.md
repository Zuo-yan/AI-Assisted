### 1.2 测试连接健壮化
- **客户端看门狗**：10 秒（200 tick）内没等到结果包就地判超时（`AiConfigFormScreen.TEST_TIMEOUT_TICKS` / `onTestTimeout`）。原因：服务端 HTTP 自身 10 秒超时，但 DNS 卡死/结果包丢失时客户端会永远停在「测试中…」。
- **迟到结果防误标**：结果包只在测试进行中被接受（init 里的监听器包了 `testingConnection` 判断）。
- **测试请求参数放宽**（`AiTestConnectionPacket`）：temperature 0.0→**1.0**、maxTokens 5→**32**。原因：Responses 协议 `max_output_tokens` 下限 16；推理系模型（o 系/gpt-5 系）拒收 `temperature≠1`。

### 1.3 第三种协议：OpenAI Responses（现在共三种）
- 新增 `core/llm/OpenAiResponsesProvider.java`（id `openai-responses`）：`instructions`/`input`、`max_output_tokens`、扁平工具声明、工具调用以 `function_call` / `function_call_output` 条目回放（无状态、不用 `previous_response_id`）、解析 `output[]`、`usage.input_tokens/output_tokens`、`incomplete(max_output_tokens)`→`length`。端点解析兼容裸域名/`/v1`/完整路径三种写法。
- `ProviderRegistry.knownIds()` = `[openai-compatible, openai-responses, anthropic]`；GUI 协议按钮自动三选循环，每种协议有独立悬浮提示（lang 键 `ai.ai_assisted.gui.provider.desc.<id>`）。
- 修正过时文案：`error.provider`（原来还写着 mock/ollama）、`/ai help` 的 provider 行；`docs/ai.md` 协议表同步。
- **协议事实（查证过，勿凭记忆）**：Chat Completions 与 Responses 是两套报文，不可互换；Responses 是 OpenAI 官方新协议（gpt-5/codex 主入口），第三方兼容服务大多不提供。

### 1.4 中转站/厂商兼容加固
- `core/llm/HttpErrors.java`（新）：非 2xx 时从错误体提取 `error.message`（OpenAI/Anthropic/中转站通用结构，兜底顶层 `message`，再兜底截断原文）。三家 Provider 统一走它——中转站错误现在是「HTTP 403：This token has no access to model xxx」这种人话。
- `AiConfig.normalizeBaseUrl`：自动剥掉玩家整段粘贴的 `/chat/completions` 后缀（否则拼出双重路径 404）。
- 传输层 `JdkHttpTransport` 本身健全（Content-Type/Accept/重定向/5xx+IO 重试），未改动重试策略。

### 1.5 长期记忆（每玩家，跨会话）
- **存储**：`core/memory/MemoryStore.java`（纯 Java，可脱离 MC 单测）。每玩家一个 JSON：`config/zuoyanmod/memory/<uuid>.json`，惰性加载、写即落盘、损坏降级为空。条目 `{id(每文件自增), text(入库截断 500 字并清除换行/尖括号), createdAt, updatedAt}`；条数到 `ai.memory.maxEntries` 挤掉最旧的并随结果告知模型。**刻意不挂 onPlayerLeave 清理**（跨会话是它的本体）。
- **玩家名字元数据**：`rememberName(uuid, name)` 由服务端自动维护（每次对话/进服刷新，名字不变不写盘），`renderForPrompt` 块首行带 `玩家名: xxx`——AI 每轮都知道在跟谁说话。
- **三个工具**（`tool/MemoryTools.java`，全员可用、无权限门槛，因为只读写玩家自己的文件）：`memory_write` / `memory_search`（空关键词=按时间倒序列出）/ `memory_forget`。总开关关闭时整组不注册。
- **注入**：`AiChatService.buildSystemPrompt` 在 `<context>` 块之后追加 `<memory>` 块（最近 `ai.memory.injectCount` 条、整块 1200 字封顶、时间正序）+ `ContextRenderer.memoryRule()`（数据非指令 + 何时写/忘的规范）。
- **命令**：`/ai memory`（=show）与 `/ai memory clear`（清空+删文件，隐私出口）。
- **配置**（Group.MEMORY，GUI 新分页「长期记忆」）：`ai.memory.enabled`（默认 true）/ `ai.memory.maxEntries`（默认 100，clamp 10..500）/ `ai.memory.injectCount`（默认 15，clamp 0..50）。

### 1.6 进服问候（AI「主动性」第一刀）
- 触发：`AiServerEvents.onPlayerLoggedIn` → `AiRuntime.greetOnJoin` → `AiChatService.greetOnJoin`。
- **独立轻量管线**（关键设计）：主线程采集事实 → **单次 LLM 调用、无工具、无历史、不写回 ChatHistory** → 回主线程 `TextPager` 分页 + `dispatcher.enqueue` 只发给该玩家。失败/空回复只记日志，**对玩家完全静默**。
- 事实数据（`collectGreetingFacts`）：玩家名、游玩总时长（`Stats.CUSTOM.get(Stats.PLAY_TIME)`）、死亡次数、在线人数、MSPT/TPS、服务器连续运行时长（`server.getTickCount()`）、游戏内天数。
- 提示词：`core/greeting/GreetingPrompts.java`（纯 Java）——`<greeting_facts>` 数据块（防注入清洗）+ 问候规则 + 模型身份声明 + 可选记忆块；`humanizePlaytime(ticks)` 服务端算好时长，不让模型做进位。
- 守卫全部**静默跳过但记日志**（`[AI] 进服问候跳过：<原因>（玩家 xxx）`）：功能关/总开关关/模型未配置/密钥未配置/并发满/冷却中（`ai.greeting.cooldownSeconds` 默认 600，防重连刷问候）。
- 配置（Group.GREETING，GUI 分页「进服问候」）：`ai.greeting.enabled`（默认 true）/ `ai.greeting.cooldownSeconds`（默认 600，clamp 0..86400）。

### 1.7 模型自我认知
- `ContextRenderer.identityStatement(AiConfig)`：把配置的模型名 + 生效协议注入**每个**系统提示词，并给常见前缀→厂商对照（gpt→OpenAI、claude→Anthropic、deepseek→深度求索、qwen→阿里通义、glm→智谱、gemini→Google、llama→Meta），要求被问「你是谁/谁研发的」时以配置模型名为准。原因：模型不知道自己被配置成什么名字，会凭训练记忆自称别家模型。

### 1.8 单人模式生命周期修复（本次最后一个 bug）
- **现象**：`HTTP 请求构造失败：Task java.util.concurrent.CompletableFuture$AsyncSupply@…` = 被截断的 `RejectedExecutionException`。
- **根因**：单人模式退出世界 → `ServerStoppingEvent` → `AiRuntime.shutdown()` → `JdkHttpTransport.close()` 关掉线程池；而 `AiRuntime` 是跨世界存活的单例，**重进世界没有任何东西重建传输层** → 同一游戏进程里第二次进世界后所有 AI 调用全灭。
- **修复**：`AiServerEvents.onServerStarted` → `AiRuntime.reload()`（重建传输/Provider）；`JdkHttpTransport` 把 `RejectedExecutionException` 翻译成人话（「HTTP 线程池已关闭…重进世界或重启游戏即可恢复」）。
- **通用教训**：单人模式里「服务器生命周期」在一次游戏会话中循环多次，凡在世界停机时关闭的资源必须在世界启动时救活。

## 2. 架构速览（接手必读）

```
org.gwfx.aiassisted
├── AiRuntime              进程级单例：config/provider/transport/所有 store 的持有者与生命周期
├── Config                 ForgeConfigSpec（TOML）定义 + 静态字段快照 + AI_SPEC_VALUES 表驱动写回
├── event/AiServerEvents   Forge 总线事件：命令注册/tick/ServerStarted/进服问候/退出清理/聊天前缀
├── chat/AiChatService     聊天编排：守卫→主线程采集→组装请求→AgentLoop→收尾分页；另有 greetOnJoin 独立管线
├── command/AiCommand      /ai 命令组（chat/goal/memory/confirm/undo/status/key/...）
├── tool/AiTools           工具注册入口：每请求现建注册表，闭包捕获 player+config；按权限/开关裁剪
├── tool/*Tool             无状态静态工具类：spec() + invoke(player, ..., args)
├── core/                  【纯 Java，CorePurityTest 禁止 MC import】
│   ├── agent/  ToolRegistry/AgentLoop/ToolArgs/ToolOutcome(4000字截断)
│   ├── llm/    Provider 三兄弟 + ProviderRegistry + HttpErrors + ToolSpec(三个 Provider 共用)
│   ├── config/ AiConfig(不可变快照,构造即夹紧) + AiConfigFields(界面字段表,唯一真相)
│   ├── context/ChatHistory + ContextSnapshot/ContextRenderer(渲染规则与数据块)
│   ├── memory/MemoryStore   ← 新增
│   ├── greeting/GreetingPrompts ← 新增
│   └── text/http/…         脱敏 / 纯 Java HTTP 传输
├── net/                   SimpleChannel 六个包（配置同步/测试连接等）
└── client/                配置 GUI（AiConfigFormScreen 基类 + 两个子类）
```

**三条铁律**（违反必出事故）：
1. 工具执行与记忆读写只在**服务端主线程**（`server.execute` 回调）；LLM/HTTP 在传输层线程。
2. `core/` 零 MC 依赖（有字节码扫描测试把关）；MC 胶水只在 `tool/`、`chat/`、`event/` 等外层。
3. 进服问候这类**主动行为**绝不能复用 `request()` 管线（会污染历史/冷却/分页），走 `greetOnJoin` 独立路径，且守卫静默跳过但记日志。

**添加一个数值配置字段的固定清单**（9 处，漏 1 就炸）：`Config.java`（spec 定义 + AI_SPEC_VALUES + 静态字段 + syncAiSnapshot）→ `AiConfig.java`（record 组件 + 夹紧，**AiRuntime.readConfig 按位置传参必须同步**）→ `AiConfigFields.java`（ALL 表 + Group + advancedGroups + **textOf switch 分支——漏了开界面直接抛**）→ 中英 lang 各两条（标签+描述，英文标签 ≤13 半角字符否则列宽测试失败）→ 测试构造点补参。

## 3. 环境注意事项

- **终端构建必须 `JAVA_HOME` 指向 `C:\Program Files\Java\jdk-17`**（IDEA 内已配置 jdk-17 不受影响）。终端默认 PATH 上的 Java 25 会让 Gradle 8.9 报 `Unsupported class file major version 69`（脚本编译失败）。
- IDEA 的 runClient 日志：`run/logs/latest.log`；旧游戏进程会占住该文件导致日志交错（注意 tasklist 里残留的 java 进程）。
- 第三方模组联调见上文 1.9；协议↔端点对齐、中转站 403（令牌分组）等排错已沉淀在 minecraft-agent-orchestrator skill 的 Fast Diagnostic Checklist（12 条）。
- 用户常用测试服务：7k7kapi.xyz（中转站，令牌对部分模型有分组限制）、api.longcat.chat（LongCat，OpenAI 兼容，**不能用 anthropic 协议**——两种协议发密钥的头不同）、api.openai.com/v1 + `/v1/responses`。
