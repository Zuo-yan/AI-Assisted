# AI 助手（内置第三方大模型接入）

状态：**已实装** · 2026-09-29 · 环境：NeoForge 26.3.0.3-beta / Minecraft 1.26.3 · modid `ai_assisted` · 版本 `2.6-neoForge-26.3`

---

## 1. 结论先说

| 项 | 值 |
|---|---|
| 是什么 | 把**你自己的**大模型密钥接进游戏的一个中文问答助手（不是内置订阅、不共享额度） |
| 怎么叫 | 按 `O` 打开界面 / 聊天里说 `ai:<问题>`（需先开开关）/ 命令 `/ai chat <问题>` |
| 谁付费 | **你自己**。密钥、额度、账单都在你自己的服务商账号上 |
| 默认状态 | **全部关闭**。不开 `ai.enabled` 和 `ai.chatPrefixEnabled` 就不会有任何网络请求 |
| 它能看什么 | 只读：周围方块与实体、自己的背包、周围容器、**你自己**的状态、服务器状态（管理员级） |
| 它能动什么 | 默认**什么都不能动**。两档危险能力（提议执行指令、按蓝图建造）各自默认关闭 + 必须玩家确认 |
| 密钥存在哪 | `config/ai_assisted/ai-secret.dat`（按机器加密），**永不写进 TOML、永不写进日志、永不下发给客户端** |

一句话：**它只在你允许的范围内读，任何"动手"都要你亲自确认。**

## 2. 开起来（三步）

### 第一步：填密钥

按 `O` → 主界面第一行的 **API Key** 输入框 → 粘贴 → 「应用」。

- 输入即覆盖，**掩码显示、不回显**，**留空 = 不修改**（不会误删）
- 要清除用 `/ai key clear`
- 密钥永远不下发给客户端：无权限的玩家打开配置界面只能**看**（模型、地址、温度、Key 来源），控件是灰的

### 第二步：选服务商（provider / baseUrl / model）

`provider` 不是"厂商"，而是**走哪套接口协议**：

| provider | 协议 | 用在 |
|---|---|---|
| `mock` | 本地回显，不联网 | **先试通用这个**：零成本确认界面/流程没问题 |
| `openai-compatible` | `POST /chat/completions`（`messages`/`choices`/Bearer） | OpenAI 本身 + DeepSeek、通义、智谱、Kimi、LM Studio、vLLM、OpenRouter、Azure、**Claude 官方兼容层** |
| `ollama` | Ollama 原生 `/api/chat` | 本地 Ollama（字段名与上面不同，才需要单列） |

常见 baseUrl（**以各家最新文档为准**，末尾斜杠有讲究，照抄）：

| 服务 | baseUrl |
|---|---|
| OpenAI | `https://api.openai.com/v1/` |
| DeepSeek | `https://api.deepseek.com/v1` |
| 通义千问 | `https://dashscope.aliyuncs.com/compatible-mode/v1` |
| 智谱 GLM | `https://open.bigmodel.cn/api/paas/v4` |
| Claude（官方 OpenAI 兼容层） | `https://api.anthropic.com/v1/` |
| LM Studio（本地） | `http://127.0.0.1:1234/v1` |
| Ollama（本地，provider 选 `ollama`） | `http://127.0.0.1:11434` |

界面上能改的就这些；`/ai status` 看当前生效值。

### 第三步：确认能通

- 游戏内：`/ai status`（需要管理权限）→ 看模型/地址/Key 来源
- 说一句：「你好」→ 有回复就通了

> ⚠️ **必看**：把 `ai.maxTokens` 从默认 1024 调到 **2048~4096**。
> 它是**输出**上限。默认值足够聊天，但"AI 建造"要模型输出一整张蓝图（几百 token 的 JSON），
> 1024 会在半截 JSON 处被截断，表现是 —— 聊天里只有「模型返回了空回复」。
> 现在这种截断会明确告诉你"回复被最大 token 限制截断"，但调大才是解决办法。

## 3. 命令一览

**所有玩家可用**

| 命令 | 作用 |
|---|---|
| `/ai chat <问题>` | 提问（等价于按 `O` 界面里输入，但不用开界面） |
| `/ai whoami` | 看**自己的**权限等级 + AI 各项能力对自己是否开放 |
| `/ai goal set <文本>` / `show` / `clear` | 给 AI 一个长期目标（会写进每次请求的 `<goal>` 块） |
| `/ai confirm` | 确认执行 AI 提议的动作（指令 / 建造） |
| `/ai cancel` | 取消待确认的动作 |
| `/ai undo` | 撤销最近一次 AI 建造（**需要 `ai.tool.adminLevel`，默认 2 级**；且不受两个总开关影响 —— 关掉开关不该锁死补救路径） |
| `/ai clear` | 清空本次对话历史（仅内存，重启也会清） |
| `/ai help` | 帮助 |

**需要管理权限**（门槛 `ai.permission.adminLevel`，默认 3 = 管理员）

| 命令 | 作用 |
|---|---|
| `/ai status` | 当前 provider / 模型 / 地址 / 各项开关 / 门槛 |
| `/ai key set <key>` / `key clear` | 设置 / 清除 API Key |
| `/ai model <名字>` / `/ai provider <id>` / `/ai baseurl <url>` | 改模型 / 协议 / 地址 |
| `/ai reload` | 重新读取配置 |
| `/ai debug context` | 把**实际发给模型的上下文**打到聊天里（排错神器，能直接看到 AI"眼里的世界"） |

## 4. 它能查什么（只读工具）

| 工具 | 说明 |
|---|---|
| 搜方块 | 在半径内按方块名/标签搜索，返回坐标与距离 |
| 搜实体 | 按实体类型搜索（玩家只以"类型 ×N"出现，**不带名字**） |
| **查配方** | 查本整合包**真实**的合成/熔炼等配方（不是模型记忆，是注册表真值） |
| 玩家状态 | 自己的血量、饥饿、经验、维度、坐标、重生点 |
| 查背包 | 按名字搜自己背包/饰品栏 |
| 查容器 | 读附近的箱子等容器内容（`ai.tool.containersReadContents`，默认开） |
| 服务器信息 | 在线人数/名单/坐标、TPS、白名单、种子（**管理员级**） |

它们**全部只读**：不写世界、不改背包、不发消息。

## 5. 两档"动手"能力（都默认关闭）

### 5.1 提议执行指令（`ai.tool.dangerousEnabled`，默认 false）

```
你：帮我执行 list
AI：（调用 propose_command）
聊天：AI 提议执行 /list（理由：…）回复 /ai confirm 执行、/ai cancel 取消（60 秒内有效）⚠ 不可撤销
你：/ai confirm → 真的执行，输出显示给你
```

四道约束：**默认关闭** + **只能提议**（模型无法独自完成一次执行，在聊天里说"确认"不算）+ **用你自己的权限集执行**（做不了你本来就做不到的事，也不绕过领地/保护插件）+ **审计日志**（`[AI][危险] 名字（等级 N）已执行 /xxx`）。

### 5.2 交互式建筑增强与建造（`ai.build.enabled`，默认 false）

AI 拥有整套建筑辅助与语义级手术能力，所有操作均**分 tick 安全执行**并记录撤销日志：

1. **从零建造蓝图（`propose_build`）**：
   - 描述需求（如「在面前建一座双层林中小木屋」），模型生成分层字符画与材料清单。
2. **定向方块清除与置换（`propose_clear`）**：
   - 对面前建筑或周围区域生效：例如「把我周围 15 格内的杂草和泥土清空」、「把面前房子的圆石全部换成深板岩砖」。
3. **建筑构件语义拆解（`propose_dismantle_component`）**：
   - 智能识别建筑的**屋顶（roof）、立柱（pillar）、门窗（window）、墙体（wall）、地板（floor）**并执行拆除：
   - 例如：「把面前建筑的屋顶拆除」、「把这栋房子的全部玻璃窗拆掉」。
4. **增量细节装饰与材质做旧（`propose_decorate`）**：
   - 为单调墙面混搭裂纹与青苔变种（做旧 weathering），或在屋檐外立面悬挂灯笼照明（lighting）。

- **确认与安全**：所有破坏或修改动作均需输入 `/ai confirm` 二次确认。
- **随时撤销**：输入 `/ai undo` 即可毫秒级原样恢复被拆除或修改的方块！

模型用**分层字符画 + palette** 设计建筑（例如 `layers: ["LLL;L.L;LLL", "WWW;W.W;WWW"]`），你确认后**分 tick** 放上去（默认 64 块/tick，不卡服）。

- 位置：只能建在**你面前**并随你朝向旋转 —— 模型拿不到也不允许指定坐标，**无法盖到别人家**
- 地形：**只能覆盖自然地形**（箱子/机器/他人建筑会让整场被拒，并报出坐标）
- 方块：禁止命令方块、结构方块、基岩、屏障、刷怪笼等 21 种
- 可撤销：`/ai undo` 反向恢复，且**只回退"仍然是我放下的那个方块"的格子**（不会吃掉别人后来的改动），并如实报告跳过几格
- 上限：`ai.build.maxBlocks`（默认 4096 格）、`ai.build.blocksPerTick`（默认 64）
- ⚠️ 不消耗背包材料
- ⚠️ 建造过程中你走远导致**区块卸载**会中止（不会为建造强行加载区块），已放置部分可用 `/ai undo` 复原

## 6. 会外发什么（隐私边界）

请求发到**你配置的**服务商，内容包含：

| 会发 | 说明 |
|---|---|
| 你的问题 + 最近几轮对话 | 对话历史只保留最终的一问一答，**不含工具调用细节** |
| `<context>` 块 | 维度、坐标、时间、天气、背包物品名、附近方块/实体（**实体只给类型 ×N，不带其他玩家名字**） |
| 附近容器的**物品名** | 可关：`ai.tool.containersReadContents=false` |
| 全服玩家**名单与坐标** | 仅当调用者达到 `ai.tool.adminLevel`；公开服请知情 |
| 指令文本 / 建造蓝图 | 仅在你打开对应开关、且模型提议后 |

| 不会发 | 说明 |
|---|---|
| **API Key** | 只用于请求头，永不进上下文、不进日志、不下发客户端 |
| 其他玩家的名字 | 除非是管理员级 `server_info` |
| 聊天记录 | 除非你打开 `ai.chatPrefixEnabled` 并触发 |
| 任何文件内容 | 本模组不读你的文件系统 |

## 7. 门槛（两个旋钮，别混）

| 配置 | 默认 | 管什么 |
|---|---|---|
| `ai.permission.adminLevel` | **3**（管理员） | 改 AI 配置：换 Key / 模型 / 地址、`/ai` 的管理类命令 |
| `ai.tool.adminLevel` | **2**（OP） | 用管理员级工具：读全服信息、提议执行指令、提议建造、`/ai undo` |

为什么后者更低：指令与建造**执行时用的是你自己的权限集**（AI 最多替你做你本来就能做的事）；
而改配置/换 baseUrl 影响**全服所有人**，所以高一档。
`ai.build.enabled` / `ai.tool.dangerousEnabled` 是**独立开关**，与门槛是"与"的关系：等级够 + 开关开，工具才会被注册。

## 8. 费用与限额

- 每次提问 = 1 次以上的 LLM 调用；**工具调用会多几次往返**（每次往返都计费）
- 每次提问的往返上限：`ai.toolMaxSteps`（默认 4）—— 这是**费用上限**，达到时会明确提示"回答可能不完整"
- 输出上限：`ai.maxTokens`（**建议调到 2048~4096**，见第 2 节）
- 每个玩家的冷却：`ai.requestCooldownSeconds`；全局并发：`ai.maxConcurrentRequests`
- 确认执行指令 / 确认建造后**不会**自动再调一次模型（省一次计费）

## 9. 排错

| 现象 | 原因与处理 |
|---|---|
| 「模型返回了空回复」 | 先看服务端日志那行 `[AI] 空回复：finish_reason=…`。若是 `length` → **`ai.maxTokens` 太小**（建造蓝图最容易撞上）。其他值（如 `content_filter`）是服务商侧拦截 |
| 聊天里提示"回复被最大 token 限制截断" | 同上，调大 `ai.maxTokens` |
| `HTTP 401` | 密钥无效/过期/复制时带了空格；重新在界面粘贴 |
| `HTTP 404` / 提示地址不对 | baseUrl 少了或多了 `/v1`（各家不同，照抄第 2 节的表） |
| `HTTP 429` | 额度或频率限制，看服务商后台 |
| AI 说"我没有这个能力" | 正常：对应工具没注册（开关没开或你的等级不够）。`/ai whoami` 能看到 |
| AI 说"我不知道" | 也正常：上下文里确实没有这条事实。这是刻意的 —— 让它承认不知道，好过编一个坐标给你 |
| 界面改了配置但没生效 | 点「应用」；若改的是 TOML 里的旧值，注意**TOML 里的值优先于默认值** |
| 建造/撤销中断，提示区块未加载 | 你走远了。回到原地再用 `/ai undo` |

排错第一招：**`/ai debug context`** —— 直接把实际发给模型的上下文打出来，AI 为什么答错一目了然。

## 10. 已知限制

- **对话历史与 `/ai goal` 都只在内存里**，服务端重启即清空（持久化属于另一个任务）
- 蓝图**不支持方块属性**：门/活板门这类有朝向的方块会用默认朝向，旋转建筑时可能不贴合
- 撤销只保留**最近一次**建造，且 10 分钟内有效（仅内存）
- **不能联网**：它答不了"去查一下 MC 百科"。原版机制靠模型自身知识 + `查配方` 工具核对真值；
  **整合包里的模组攻略它可能不知道**，此时按规则会明确说"这是推测" —— 请以 mcmod.cn / 官方 wiki 为准
- 不消耗材料，等于给有权限的人开了一个刷建材的口子（门禁：等级 + 默认关闭 + 玩家确认）
